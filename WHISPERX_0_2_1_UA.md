# Foundation 0.2.1 — перша ASR-чернетка у реєстрі

Цей випуск додає незалежний адаптер WhisperX до контролера Foundation. Старі worker_auto.py, Start_Auto.bat, venv і результати не змінюються. Їхня архітектура не переноситься; використовуються API встановленого WhisperX та вже реалізований журнал Foundation. Профіль: large-v3, CPU int8, batch 4, VAD із встановленого WhisperX, alignment окремим етапом. Інші параметри ASR залишаються defaults саме наявного WhisperX, як у наданому worker_auto.py.

## Що вже підтверджено локально

Python 3.10.11 x64; WhisperX 3.8.7rc1 із Git commit 2cfd7b7c5c7bba144954364db747319b50e8232b; faster-whisper 1.2.1; CTranslate2 4.8.1; Torch/torchaudio 2.8.0; numpy 2.2.6. Torch без CUDA, тому старий worker з auto обирає CPU. CTranslate2 бачить GPU, але це не доводить виконання моделі на ній.

Попередня проба завантажила large-v3/VAD та українську alignment-модель. VAD відкинув тон, тому вона не підтвердила декодування мовлення. У великому реальному записі ASR завершився, обидва канали визначено як ru, але російський alignment не завантажився: залишено ASR timestamps. Реальна швидкість у пробі з паралельним навантаженням не виміряна надійно.

## Перша перевірка нового адаптера

1. Закрийте попередній Foundation, розпакуйте 0.2.1 в окремий каталог. Збережіть попередні випуски та перевірену резервну копію.
2. Запустіть Run_Tests.bat. Очікується 51 тест та OK. Тести не відкривають вашу справу.
3. Запустіть Start_Foundation.bat, оберіть ваш існуючий робочий каталог та наявну справу. Повторного приймання, поділу чи імпорту LVA немає.
4. Натисніть «Транскрибація». За замовчуванням обрані whisperx, cpu, Python C:/WhisperX/venv/Scripts/python.exe та коротка проба.
5. Увімкнену коротку пробу залиште. Введіть 30–60 секунд реального мовлення у форматі MM:SS або MM:SS.mmm. Початок та кінець відраховуються від початку оригінального WAV. Оберіть ділянку з репліками обох учасників; за можливості межі на паузах. Максимум короткої проби — 2 хвилини. Не вводьте кадри. Проба не змінює межі частин LVA, зокрема вашу 16:10.400.
6. Мова auto повторює поведінку старого запуску й визначається окремо для кожного каналу. Для розмови, мова якої відома, можна явно обрати ru або uk; це змінює параметри запуску і потребує окремої оцінки результату. Для першого відтворення попереднього auto-запуску збережіть auto.
7. Alignment policy залиште keep_asr. Це збереже текст навіть за помилки alignment, але покаже явний fallback. Натисніть «Запустити». Інші транскрибації на цей час не запускайте.
8. Після завершення натисніть «Відкрити текст» і перевірте фрагмент за аудіо: слова, роль учасника, приблизні межі фраз, наявність пропущених або зайвих реплік. Коротка проба може відрізнятися від повного запису через обмежений контекст і межі; вона перевіряє інтеграцію, а не заміняє повний транскрипт.
9. У головному Foundation виконайте «Перевірити». Якщо issues порожній, створіть нову резервну копію й перевірте її. Повний запуск обох каналів виконуйте після оцінки короткої проби, знявши прапорець короткої проби.

Не запускайте Setup_ASR.bat, Download_ASR_Model.bat або Probe_ASR.bat для цього маршруту: вони належать окремому faster-whisper-профілю 0.2.0. Старий venv не оновлюється. Нова програма не викликає worker_auto.py; вона запускає власний адаптер тим самим Python.

## Як використовуються локальні моделі

Перед запуском адаптер знаходить вже кешовану large-v3 через faster-whisper local_files_only, перевіряє контрольні версії та Git commit WhisperX. В models/whisperx_reference/MODEL_MANIFEST.json створюється опис-посилання з хешами ASR-файлів і Pyannote VAD asset. Самі файли кешу не копіюються, не оновлюються та не перезаписуються. Опис містить локальні шляхи; не надсилайте його без потреби.

Пакети, код WhisperX і Torch build-файл також ідентифікуються для запуску. Зміна контрольного середовища або ASR/VAD-файлів блокує повторне використання опису, а не виправляється автоматичним оновленням. Якщо опис уже існує й середовище змінилося, збережіть помилку для контрольованої нової ревізії опису.

Обробка використовує offline-параметри та блокування стандартних Python-мережевих операцій audit hook. Відсутні моделі не завантажуються під час роботи з аудіо. Це не системна мережева ізоляція від довільного native-коду бібліотек.

## Статуси і результат

- ASR COMPLETED: текст отримано; точність не затверджена.
- ASR NO_SPEECH_DETECTED: для каналу немає сегментів. Це не підтвердження якості VAD або справжньої відсутності мовлення; канал треба перевірити.
- Alignment COMPLETED_UNREVIEWED: етап alignment виконався. Час має ALIGNED_UNREVIEWED, але потребує перевірки. Окремі слова можуть не мати часу; WORD_TIME_MISSING зберігається явно.
- Alignment FAILED_ASR_TIMES_RETAINED: етап не виконався або результат непридатний; текст і ASR_ESTIMATED збережені. Причина в channel_statuses та сирому результаті. Позначка присутня в TXT/MD/JSON і попередженні GUI.
- Alignment NOT_APPLICABLE_EMPTY: немає ASR-сегментів для alignment.

Режим require блокує архівування каналу з текстом, якщо alignment не завершився. У цьому режимі completed означає виконання етапу, а не ручне затвердження всіх слів. Порожній канал лишається попередженням, а не успішною перевіркою мовлення. За збою поточний незавершений канал виконується заново; завершений канал має перевірену контрольну точку.

Усі результати DRAFT_UNREVIEWED. Статус часу LVA не змінюється; автоматичного затвердження прив’язки LVA немає. Сирий ASR-результат зберігається окремо від нормалізованого результату alignment у JSON каналу. Для успішного aligner зберігається ім’я/ревізія за доступності та SHA-256 його weights. Для короткої проби сирий ASR має відносний час фрагмента; нормалізовані utterances/words мають час від початку оригіналу. Window містить точні кадри й sample_rate для аудиту; користувач вводить лише час.

Один запуск додає 12 артефактів: опис запуску, 2 сирі JSON та 9 експортів JSON/TXT/MD для обох учасників, інтерв’юера й респондента. XLSX і редактор транскрипту ще не реалізовані. Короткий запуск позначено SHORT_SPEECH_TEST; повний FULL_CHANNELS. Вони не підміняють один одного.

Повторний запуск з тими самими умовами поверне існуючу чернетку. Це стосується також завершеної чернетки з alignment fallback. Після виправлення alignment для повторної перевірки позначте «Нова ревізія»: обидва канали будуть розпізнані заново, а попередні артефакти збережуться. Перевиконання лише alignment без ASR ще не додане.

Моно джерела — зареєстровані точні канали, не нормалізований Audacity-файл. Для рушія декодуються float32 семпли й робиться ресемплінг до 16 kHz, як у контрольному worker; архівні WAV не змінюються. Нормалізації/фільтрації для LVA немає. Діаризація не використовується, бо ролі вже підтверджені за каналами.

Обробка каналів послідовна в окремих процесах. Прогрес показує етап, а не достовірний відсоток чи залишковий час. timings_seconds розділяє завантаження моделі, ASR, alignment і selected_audio; total не включає перевірку кешу контролером та архівування. Швидкість короткого фрагмента не екстраполюйте без перевірки на повний запис.

## Межі перевірки і резервування

51 автоматичний тест на синтетичних даних пройдено в Linux. Нові тести перевіряють fallback, require, часовий зсув/межі проби, незмінність сирого ASR, provenance aligner, відмінність ревізій і блокування пошкодженого VAD. У тестах підставлений штучний рушій/aligner. Реальні WhisperX API, Windows GUI, кеш і цей новий адаптер ще потребують локального запуску.

Резервна копія реєстру включає завершені зареєстровані ASR-артефакти, але не venv, кеш моделей, опис у каталозі програми чи незавершені _asr_jobs. Для відновлення обчислювального середовища збережіть наявний список залежностей/Git commit і моделі окремо. Контроль хешів є перевіркою випадкового пошкодження, а не захистом від адміністратора, який може змінити дані та описи.

Для зворотного зв’язку достатньо: підсумку Run_Tests, scope, кількості utterances, статусів ASR/alignment, timings_seconds, кількості артефактів та issues після Verify, і вашої оцінки тексту/часу. Не надсилайте WAV, повний manifest, raw JSON або приватний транскрипт.
