# Окремий faster-whisper-профіль із Foundation 0.2.0

У випуску 0.2.1 для вашого наявного WhisperX використовуйте WHISPERX_0_2_1_UA.md. Наведені нижче Setup/Download/Probe належать попередньому альтернативному профілю. У GUI 0.2.1 для нього потрібно явно обрати faster-whisper.

Профіль вашого ПК: Windows, Python 3.10.11 x64, приблизно 16 GB RAM, RTX 3050 Laptop 6 GB, драйвер 577.05. Діагностика підтвердила обладнання, але не CUDA/cuDNN або запуск моделі. Для першої проби використовується multilingual large-v3, GPU `int8_float16`, один канал за раз. Достатність VRAM для реального запису ще не перевірена. Torch не потрібен.

## 1. Оновлення без повторного приймання

Закрийте попередню програму та розпакуйте пакет в окремий каталог. Збережіть попередній випуск і вже перевірену резервну копію. Робочий каталог з registry.sqlite та cases залишається вашим існуючим каталогом. Схема реєстру v1 сумісна; справу, канали, частини й LVA повторно не імпортуйте. Межа 16:10.400 залишається чинною.

Запустіть `Run_Tests.bat`; очікується 38 тестів та `OK`. Тести використовують штучні дані, не вашу справу.

## 2. Підготовка пакетів

Запустіть `Setup_ASR.bat`. Потрібен інтернет. Скрипт створить окреме середовище `.venv_asr` через Python 3.10, встановить пакети і перевірить їхні залежності. Глобальні пакети Python, включно з вашим numpy, не змінюються.

Прямі версії закріплені: faster-whisper 1.2.1, CTranslate2 4.8.2, numpy 2.2.6. Транзитивні залежності підбирає pip; повний фактичний набір фіксується в `ASR_INSTALLED_LOCK.txt`. Це не повністю закріплена відтворювана збірка всіх залежностей. Повторний Setup може оновити транзитивні пакети; зберігайте цей файл після успішної проби.

## 3. Підготовка моделі

Запустіть `Download_ASR_Model.bat`. Потрібен інтернет і кілька гігабайтів вільного місця. Скрипт завантажує `Systran/faster-whisper-large-v3`, спочатку визначає конкретну ревізію репозиторію, потім завантажує саме її. Ревізія та SHA-256 файлів записуються в `models/large-v3/MODEL_MANIFEST.json`.

Успіх: `MODEL_VERIFIED` або `MODEL_ALREADY_VERIFIED`. За помилки припиніть підготовку й надішліть текст помилки. Не підміняйте модель іншими файлами. Пошкодження вже підготовленої моделі блокує запуск і не виправляється тихим перезаписом.

## 4. Реальна проба рушія без приватного запису

Запустіть `Probe_ASR.bat`. Він перевіряє GPU-профіль, локальні DLL, модель та виконує розпізнавання однієї секунди штучної тиші. Аудіо вашої справи не відкривається, реєстр не змінюється. Перший запуск може зайняти час; миттєвого результату не очікуйте.

Успіх: JSON зі `status: ENGINE_SMOKE_TEST_PASSED`, `device: cuda`, `compute_type: int8_float16`. Надішліть цей JSON або повідомлення `NOT_READY`. Проба підтверджує запуск рушія, але не якість транскрипції або достатність пам’яті на всьому записі.

Для GPU актуальний faster-whisper потребує CUDA 12/cuBLAS та cuDNN 9. Драйвер NVIDIA сам по собі не підтверджує їх встановлення. Setup не встановлює системні CUDA/cuDNN або драйвер. Якщо Probe повідомить про відсутню DLL, знадобиться Windows-варіант CUDA 12 і cuDNN 9 для CUDA 12 за офіційними інструкціями. CUDA 13 не є обраним профілем цього пакета.

Якщо бібліотеки вже встановлені, але не знаходяться, додайте їхні фактичні bin-каталоги у `dll_dirs` в `ASR_SETTINGS.json`, наприклад:

```json
{"device":"cuda","language":"auto","dll_dirs":["C:/actual/cuda/bin","C:/actual/cudnn/bin"]}
```

Шляхи в прикладі умовні: замініть їх реальними каталогами. У разі проблем спочатку надішліть результат Probe; не змінюйте системні бібліотеки навмання.

CPU — окремий явний профіль: поставте `device: cpu` в ASR_SETTINGS.json, повторіть Probe, потім оберіть cpu у вікні транскрибації. Використовується та сама large-v3 з `int8`. Після GPU-помилки автоматичного переходу на CPU немає.

## 5. Перша транскрибація після успішної проби

Відкрийте `Start_Foundation.bat`, оберіть ваш існуючий робочий каталог і справу. Натисніть «Транскрибація». Альтернатива — `Start_ASR.bat`, де каталог і справу потрібно ввести самостійно. Підтвердьте пристрій та мову; auto визначає мову окремо на кожному каналі. Якщо мова розмови відома, можна явно обрати uk, ru, be, az, kk або et.

Джерела ASR — зареєстровані точні моно канали, витягнуті з оригіналу. Старий нормалізований в Audacity WAV не використовується як їх заміна. Обробляються цілі канали: інтерв’юер, потім респондент; межі частин LVA не розрізають ASR. VAD вимкнено. Потрібне рушію декодування/ресемплінг не змінює архівний WAV. Час відраховується від початку оригінального аудіо; точність ASR-позначок потребує ручної перевірки.

Модель працює в окремому процесі. Прогрес показує канал і кількість сегментів; це не оцінка залишкового часу. На час операції діє блокування запису реєстру. Резервування й інші операції запису виконуйте після завершення ASR.

«Зупинити» завершує поточний процес. Уже повністю завершений канал зберігається як перевірена контрольна точка. Після повторного запуску з тим самим джерелом, моделлю, параметрами та версіями пакетів він буде використаний повторно. Незавершений канал розпізнається заново від початку. Контрольні точки в `_asr_jobs` ще не входять у резервну копію реєстру; резервування охоплює результати після їх завершеного архівування. Локальні журнали помилок можуть містити шляхи — перегляньте їх перед передаванням.

## Результат і межі етапу

Усі результати отримують `DRAFT_UNREVIEWED`. Це чернетка без затвердження тексту, слів і часу. Порожній канал позначається попередженням у описі запуску. Дані LVA та їхній статус UNVERIFIED не змінюються.

Реєстр отримує 12 нових артефактів: опис запуску, два сирі результати каналів і **9 транскриптних експортів** — JSON/TXT/MD для обох каналів, інтерв’юера та респондента. XLSX, редактор/затвердження транскрипту та узгодження з LVA — наступні модулі. Повні 12 транскриптних експортів із архітектури ще не реалізовані.

Файли мають архівні UUID-імена. Їхні типи та вибір каналів показані у `cases/<ID>/manifest.json`, поле metadata. Після завершення натисніть «Перевірити», потім створіть та перевірте нову резервну копію. Повторний запуск з ідентичними параметрами поверне вже наявну чернетку; зміна пристрою або мови створить окремий запуск без перезапису попереднього.

У цьому випуску 38 автоматичних тестів контролера/основи проходять у Linux на штучних даних. Тести ASR підставляють штучний рушій: реальна модель, Windows, GPU, CUDA/cuDNN та якість приватного запису тут не перевірені. Для цього потрібні Probe і подальша локальна перевірка транскрипту. WAV надсилати не потрібно.
