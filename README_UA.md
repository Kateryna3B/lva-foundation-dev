# LVA Foundation 0.2.1 — перший пілот

Пакет реалізує початковий етап узгодженої архітектури: приймання WAV та Excel-бланка, облік справ і осіб, архівування вихідних файлів, витягнення каналів без перерахунку семплів, підтверджені частини, сирий імпорт LVA CSV, резервування та перевірку цілісності. Обробка аудіо локальна. Для первинної підготовки ASR окремі скрипти завантажують пакети й модель; аудіо вони не читають.

## Поточний ASR-маршрут 0.2.1

Для вашого наявного середовища C:/WhisperX/venv читайте WHISPERX_0_2_1_UA.md. У вікні ASR за замовчуванням WhisperX CPU int8 batch 4 і коротка проба обох каналів. Встановлення нового середовища не потрібне. Інструкція ASR_SETUP_UA.md описує попередній окремий faster-whisper/GPU-профіль і не є маршрутом цієї проби.

## Запуск на Windows

1. Розпакуйте ZIP у окремий каталог. Потрібен встановлений Python 3.10 або новіший з tkinter та командою `py`. Для функцій основи інсталяції пакетів через pip не потрібні. ASR готується окремо за ASR_SETUP_UA.md. IANA tzdata та її ліцензії включені.
2. Спочатку запустіть `Run_Tests.bat`: усі тести працюють на штучних даних у тимчасовому каталозі.
3. Запустіть `Start_Foundation.bat` і оберіть порожній локальний робочий каталог, наприклад `D:\LVA_Pilot`. База SQLite не призначена для мережевого диска/NAS. Автовизначення мережевих дисків з літерою поки відсутнє — їх не обирайте.
4. Натисніть «Чистий бланк», заповніть блакитні клітинки в Excel та збережіть. Не змінюйте ключі полів, назви аркушів чи Schema. У режимі `new` задайте латинський псевдонім, залиште ID порожнім. Для наявної особи оберіть `select` та скопіюйте ID з кнопки «Особи». Однакові псевдоніми допускаються; різні особи мають різні UUID.
5. Натисніть «Приймання», оберіть бланк та оригінальний WAV. Оригінал копіюється побайтово; ваша вихідна копія не змінюється. Збережіть показаний ID справи — він також потрапить у поле вікна.
6. Прослухайте канали самостійно. Натисніть «Витягнути канали» та явно підтвердіть канал респондента. Канали нумеруються 1 і 2. Нормалізації, видалення пауз, ресемплінгу немає. Змішаний запис блокує цей маршрут.
7. Натисніть «Частини». Програма покаже тривалість і внутрішні межі у часі. Для двох частин введіть одну межу, для трьох — дві, у форматі `MM:SS`, `MM:SS.mmm` або `MM:SS,mmm`. Наприклад `16:10.400`. Початок і точний кінець WAV програма додає сама. Перевірте межі за аудіо, позначте відповідний прапорець і натисніть «Створити частини». Якщо частини вже є, вікно лише показує їхні інтервали. У пілоті немає вбудованого плеєра/VAD і автоматичного пошуку завершення фрази. Рівні межі — лише початкова пропозиція, не підтвердження змістовної межі.
8. «Перевірити» повертає кількість артефактів та `issues`. Порожній список означає, що всі зареєстровані файли на момент перевірки відповідають SHA-256.

Правило кількості частин: до 20 хв включно — 1; понад 20 та менш ніж 45 — 2; від 45 до 60 включно — 3. Понад 60 хв приймання зберігає джерело, але витягнення каналів заблоковане до окремого маршруту ручного зовнішнього поділу. Усередині системи межі залишаються цілими індексами кадрів: 0, внутрішні межі, загальна кількість кадрів. Введений час перераховується в найближчий кадр; рівно половина кадру округлюється до пізнішого. Початкові введені позначки й правило перерахунку зберігаються у метаданих. Інтервали напіввідкриті `[start, end)`; пропуски й подвійне включення неможливі при валідному списку. Зміна вже підтвердженого каналу або меж поки блокується; механізм ревізій — наступний модуль.

## Старий аналіз LVA

У «Імпорт LVA» виберіть ID зареєстрованої частини з `cases/<ID>/manifest.json`. Для старого аналізу цілого запису введіть `LEGACY_FULL`. Оберіть **саме WAV, який аналізувався у LVA**, та відповідний CSV. Нормалізований в Audacity файл можна зберегти як окремий вхід LVA: він не підміняє оригінал або точний канал.

Імпорт зберігає побайтові WAV/CSV та JSON з усіма початковими полями, категоріями, відсутніми значеннями, числовими значеннями й окремими UUID сегментів. Підтримується лише спостережений 26-колонковий CSV-профіль LVA 6.50; порожня 27-ма колонка заголовка допускається. Інше кодування, формат і TF6/lvaInf потребують наступних адаптерів. Число 0, порожня клітинка та помилка числового розбору різняться. Від’ємні числа зберігаються.

Статус часу завжди `UNVERIFIED`. Час CSV — кандидат у мікросекундах за спостереженим синтаксисом; автоматичного перенесення на оригінал немає. Вхід WAV має відповідати тривалості області; нормалізація не є доказом збігу семплів. Імпорт повторного CSV зараз створює окремий артефакт, не автоматично об’єднаний аналіз. Категорії LVA зберігаються як дані джерела; програма не формує висновок про правдивість.

Раніше підтверджені 6 контрольних моментів належать лише перевіреній парі файлів, з виправленим шостим моментом **32:12,027**. Цей пакет не застосовує ту перевірку до інших записів і не вносить часову поправку.

## Відновлення та резервна копія

Журнал має стани WRITING, PREPARED, COMMITTED. «Відновити» продовжує PREPARED тільки після перевірки хешів, відновлює manifest із бази та прибирає staging успішних операцій. WRITING без повного плану залишається як `INTERRUPTED_RETAINED`: автоматичного видалення невідомих даних немає. Повторіть відповідну операцію після перегляду помилки. Якщо копіювання кінцевого файла було обірване посередині або хеш не збігається, автоматичне відновлення блокується; пошкоджений файл не перезаписується. Потрібна окрема процедура розбору такого збою. Це обмеження пілота, а не гарантія відновлення після будь-якого вимкнення живлення.

«Резервувати» створює новий каталог поза робочим, узгоджену копію SQLite та всіх зареєстрованих артефактів. Лише на завершенні з’являється `COMPLETE.json`. Неповна копія без цього файла не є готовою резервною копією. Реєстр блокується на час резервування; manifest є відновлюваною проєкцією, тому його не потрібно копіювати.

Перевірка готової копії: натисніть «Перевірити копію» й оберіть конкретний каталог `backup_…`, у якому є `COMPLETE.json`. Це окрема перевірка копії, вона не замінюється кнопкою «Перевірити» робочої справи. Очікується `checked_files` та порожній `issues`. Вона не відкриває і не змінює базу резервної копії. Командний варіант також залишається:

```bat
py -3 Verify_Backup.py "E:\Backups\backup_UUID"
```

Для пробного відновлення після успішної перевірки скопіюйте вміст резервного каталогу в **новий порожній локальний каталог**, оберіть його в програмі, натисніть «Відновити», потім «Перевірити». Не підміняйте працюючу базу. Розклад резервування, NAS-реплікація і контроль строків зберігання ще не реалізовані.

## Командний інтерфейс

Відкрийте термінал у каталозі пакета. Справу можна вибрати UUID або кодом C…:

```bat
py -3 -m lva_system --root "D:\LVA_Pilot" init
py -3 -m lva_system --root "D:\LVA_Pilot" intake --form "D:\Intake.xlsx" --audio "D:\Original.wav"
py -3 -m lva_system --root "D:\LVA_Pilot" list
py -3 -m lva_system --root "D:\LVA_Pilot" people
py -3 -m lva_system --root "D:\LVA_Pilot" prepare --case UUID --respondent-channel 2
py -3 -m lva_system --root "D:\LVA_Pilot" parts --case UUID --times "16:10.400"
py -3 -m lva_system --root "D:\LVA_Pilot" import-lva --case UUID --input "D:\LVA_Input.wav" --csv "D:\Export.csv" --legacy-full
py -3 -m lva_system --root "D:\LVA_Pilot" verify --case UUID
py -3 -m lva_system --root "D:\LVA_Pilot" recover
py -3 -m lva_system --root "D:\LVA_Pilot" backup --destination "E:\Backups"
```

UUID замініть реальним ID; `--times` приймає лише внутрішні межі. Для однієї частини передайте `--times` без значень, для трьох — дві часові позначки. CLI `--boundaries` залишається для сумісності технічного режиму кадрів; графічний інтерфейс його не вимагає. Такий самий WAV і той самий зміст бланка повертають наявну справу. Те саме аудіо з іншим бланком блокується; навмисне створення іншої справи дозволяється тільки CLI-параметром `--allow-new-case`.

## Межі цієї версії

Це пілот основи, а не завершена система. Реалізовано пілот ASR та 9 транскриптних експортів JSON/TXT/MD. Повні 12 експортів (включно з XLSX), ручна корекція/ревізії, затвердження часової прив’язки LVA, локальний LLM, сервіс із окремим Windows-обліковим записом та захищені ACL, шифрування, ретенція, планові копії й набір даних будуть окремими модулями. Наявні файли не перезаписуються штатними операціями, але поточна програма не забороняє користувачу або адміністратору змінити їх через файлову систему; SHA-256 виявляє таку зміну під час перевірки. Архівні матеріали та журнал не мають криптографічного захисту від адміністратора.

Підтримується RIFF/WAVE PCM 16/24/32 та IEEE FLOAT 32/64, включно з extensible PCM/FLOAT. RF64, PCM8, стиснені WAV, кілька data chunks та невідповідний розмір RIFF відхиляються явно. Метадані додаткових WAV chunks зберігаються в побайтовому оригіналі; у похідні моно переносяться формат і семпли.

Тестування цього випуску проведено в Linux на синтетичних файлах. Windows-інтерфейс, гілка msvcrt блокування, Excel на вашому ПК та реальний приватний WAV потребують локального пілота. Не надсилайте WAV чи повний manifest: він містить персональні поля. Для зворотного зв’язку достатньо підсумку тестів і повідомлення про помилку без приватних даних.

## Наступна реалізація

Локальна транскрибація з версіями запусків та контрольними точками додана у 0.2.0; наступні модулі — перевірка/редагування транскрипту та затвердження часової прив’язки LVA. Перед підключенням реальних справ потрібно завершити сховище з окремими Windows-правами й процедуру відновлення після обірваного копіювання. Пілотна схема реєстру v1 не є незмінним контрактом усієї майбутньої системи: міграція буде явною, з резервною копією.

## Оновлення 0.1.1: діагностика псевдонімів

Виправлено загальне повідомлення, яке не розрізняло замовника й респондента. Нова помилка називає поле, клітинку Intake!C8 або Intake!C12 та причину: порожнє значення, понад 40 символів або позиція недопустимого символу з Unicode-кодом. Правило 1–40 латинських літер A–Z/a–z не змінено; цифри, внутрішні пробіли та кирилиця не дозволені. Псевдонім NewResp проходить перевірку.

Програма читає збережений XLSX на диску, а не незбережений стан відкритого Excel. Перед повторним прийманням збережіть бланк (Ctrl+S) та виберіть саме його копію. Якщо причина залишиться незрозумілою, для перевірки потрібен заповнений XLSX; WAV надсилати не потрібно.

Для оновлення закрийте попередню програму, розпакуйте цей випуск в окремий каталог і запустіть його Start_Foundation.bat. Оберіть той самий робочий каталог. Міграції схеми немає: registry v1 сумісний, робочі дані не треба переносити або видаляти.

Перевірено 20 автоматичних тестів на синтетичних даних у Linux, включно з новими перевірками діагностики й латинсько-кириличного змішування. Повторний запуск 0.1.1 на Windows ще не перевірений тут.


## Оновлення 0.1.2 і перехід до транскрибації

Реалізовано введення часу для меж частин та кнопку перевірки резервної копії. Структура registry v1 сумісна. Розпакуйте новий випуск окремо, закрийте стару програму й оберіть у новій той самий початковий робочий каталог. Не повторюйте приймання, створення частин або імпорт уже наявного аналізу. Ваша межа 16:10.400 чинна. Кнопка «Частини» покаже створені раніше частини без їх зміни. За потреби виберіть справу за наявним UUID.

У CLI можна переглянути план без створення аудіо:

```bat
py -3 -m lva_system --root "D:\LVA_Pilot" parts-plan --case UUID
```

29 автоматичних тестів пройдено у Linux на синтетичних файлах. Новий Tkinter-діалог перевірено статично; запуск його на Windows тут не виконано. Пілот 0.1.1 раніше успішно перевірений користувачем на Windows, але це не підміняє перевірку нового інтерфейсу.

Наступний модуль — локальна ASR. Запустіть `Check_ASR_Environment.bat` і надішліть виведений JSON. Він містить версію Python, розрядність, обсяг RAM (на Windows), NVIDIA GPU/драйвер за доступності nvidia-smi та версії вибраних пакетів. Він не читає аудіо, не завантажує моделі, не встановлює пакети й не виконує транскрибацію. Відсутність nvidia-smi не доводить відсутності GPU. Наявність пакетів не доводить сумісності CUDA чи працездатності моделі — це наступна окрема перевірка.
