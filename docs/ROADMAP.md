# План і контрольні точки

| Точка | Зміст | Критерій виходу |
|---|---|---|
| B0 | Джерельний baseline 0.2.4 | ZIP звірений, Git tag; це не приймання всього продукту |
| O1 | Організація | Git bundle відновлюється; документація й промпти доступні; код не змінений |
| S1 | Стабілізація | Word validation, reused/open, create/open workspace; тести; діагностика хвостів із доказами |
| R1 | Ручна перевірка | Аудіо/текст/межі, нова ревізія, provenance, попередня версія збережена |
| X1 | Time map та XLSX | N:M без подвійного обліку, видимі неперевірені зв’язки, 12 узгоджених експортів |
| W1 | Windows-приймання | Повний uk/ru-процес, повторний запуск, переривання, відновлення в новий каталог |
| E1 | Розширення | Parquet/GPU/AMD/NAS/LLM окремими прийнятими змінами |

Можна паралельно робити S1-ASR, S1-storage і незалежні QA-тести. Схему звіту можна проєктувати на синтетичних даних; фінальне зіставлення залежить від time map і станів перевірки. Не вводити обов’язковий Parquet, автоматичний VERIFIED чи Cognitive Pause за тривалістю. Пороги тривалості записів: ≤20 хв — 1 частина; >20 і <45 — 2; 45–60 включно — 3; >60 — спеціальна обробка/ручний поділ.

Подальші функціональні зміни ще не виконані цим пакетом. Часові оцінки планувати після декомпозиції; кількість агентів сама по собі не є обіцянкою прискорення.
