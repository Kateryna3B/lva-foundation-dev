# Розробка, інтеграція та відтворення

Базовий commit `86d60556b046a49c502e2a6e7cb188a9cdf2cb04`, tag baseline-v0.2.4. Організаційний tag org-v0.2.4-1 додає документацію. Remote не налаштовано й нікуди не опубліковано. Bundle у пакеті — переносна копія Git-історії; .git папка в source не потрібна.

## Відновлення репозиторію (Git має бути встановлений)
З кореня розпакованого ZIP:
```bat
git clone LVA_Foundation.bundle LVA_Development
cd LVA_Development
git log --oneline --decorate -5
git tag --list
```
Для окремої робочої копії базового коду:
```bat
git worktree add ..\LVA_Baseline baseline-v0.2.4
```
Команди не змінюють реєстр справ. Не використовувати reset --hard у каталозі з незбереженими змінами.

## Порядок робіт
Task ID → base commit → allowlist → окрема гілка/worktree → зміна → релевантні тести → звіт → ревізія головним агентом → послідовна інтеграція → інтеграційні тести → release candidate → Windows-приймання.

Головний агент є власником core.py, asr.py, заголовків/версії, схем і пакування; передає редагування конкретній задачі явно. Два агенти не редагують ці файли одночасно. Нові ізольовані модулі можна писати паралельно. Кожен агент називає базовий commit; застарілий patch повторно перевіряється після інтеграції інших робіт.

Прийняти patch можна тільки після перегляду diff, відповідності контракту, позитивних і негативних тестів, оновлення документації та відсутності неприйнятного регресу. Слова «тести пройдено» без команди/середовища/результату не є доказом. Якщо зміни стосуються GUI/Windows, окремо позначати що локально не перевірено.

## Випуск
Версія програми й версія контракту ASR різні: UI з __version__, контракт змінюється коли змінено значення результату/кешу. Пакет org1 залишає controller_version 0.2.2 для WhisperX (0.2.0 для faster-whisper) навмисно. Кожен ZIP має одну однойменну кореневу папку, SHA-256, release note і acceptance report. Старі теги не переміщувати. Нову схему БД без migration/backup plan не приймати.

Код і коментарі нових модулів — англійською, UI/інструкції — українською. Не переписувати весь legacy-код лише заради стилю. Репозиторій містить код, синтетичні fixtures і документацію, не інтерв’ю, реєстри, моделі або секрети.
