# Відомі проблеми

Усі нижче OPEN; цей організаційний випуск їх не виправляє.

| ID | Пріоритет | Доказ / наслідок | Наступна дія |
|---|---|---|---|
| K01 | P1 | 8 довгих кінцевих слів у повному тесті | raw ASR ↔ aligned ↔ WAV; не обрізати автоматично |
| K02 | P1 | validate_result перевіряє репліки, не повний words-контракт | незалежний валідатор вкладених слів |
| K03 | P1 | reused не повертає review_files | однаковий контракт результату, тести відкриття |
| K04 | P1 | Store.__init__ створює БД автоматично | окремі create/open; відкриття без запису до валідації |
| K05 | P1 | duration equality не доводить походження LVA input | time map і provenance |
| K06 | P2 | stage може залишатися RECEIVED після ASR | проєкції окремих напрямів, не один лінійний стан |
| K07 | P2 | writer lock на час всього ASR | документувати однокористувацький режим; concurrency окремо |
| K08 | P1 | частковий кінцевий файл може блокувати recover | сценарій діагностики/відновлення без overwrite |
| K09 | P2 | немає зручного переліку справ | вибір із списку; зараз ручний ID |
| K10 | P1 | ru alignment раніше не завантажився | перевірити кеш/залежності без знищення робочого venv |
| K11 | P2 | PID/індикатор не доводять прогрес обчислень | трактувати як живий процес/інтерфейс; не як % готовності |

P1 — до приймання відповідного робочого сценарію; не означає, що треба негайно змінити всі модулі одним комітом. Кожне виправлення має окремий task_id, тест і запис у CHANGELOG.
