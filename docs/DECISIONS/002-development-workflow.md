# ADR-002 — компактний керований процес розробки
Дата: 2026-10-07. Статус: організаційний регламент оновлено в затвердженій моделі головного інтегратора. Зовнішні підключення — рекомендації, ще не виконано/не погоджено до публікації.

Контекст: спроба S1-A зупинена usage limit; функціональних патчів не збережено. Замовник надав зовнішню концептуальну рецензію Gemini і просить врахувати її без перенесення інженерної роботи на себе.

Рішення: один головний архітектор/диспетчер/інтегратор, короткі task cards та versioned contracts, один виконавець за замовчуванням, незалежний QA після candidate. Два виконавці — умовна оптимізація, не обов'язковий склад. PROJECT_STATE — індекс підтвердженого стану. Замовник отримує зведений звіт і питання щодо суттєвих рішень, не файли для ручного merge.

Альтернативи: окремий чат-архітектор та замовник-шлюз збільшують ручне навантаження; постійні три паралельні агенти дублюють контекст; лише один агент без незалежного review послаблює gate для часу/даних. Обрана схема зберігає незалежну перевірку на завершеному snapshot.

Наслідки: не гарантуємо економію токенів; порівнюємо прийняті задачі, переробки, регресії, час і доступні фактичні лічильники. Менша паралельність може подовжити хвилю, але обмежує повторне читання. Критичні рішення root перевіряє сам.

Інструменти: private GitHub — рекомендовано; Drive/Docs — допоміжно; окремий paid Workspace і дублюючий Sheets tracker зараз не потрібні. Створення repo/push/платних ресурсів не виконано. Runtime лишається Windows/offline.
